# CRS-11 관측에 맞춘 물리 기반 입력·파라미터 추정

`flight_calibrated_*`는 공개 고도·속력 관측에 맞춰 입력과 불확실한 모델 파라미터를
추정한 별도 시나리오다. **현재 착륙은 LCvx 유도·PD 제어의 폐루프**로 실행한다.
첫 네 구간은 추정된 입력 시간표를 사용한다. 각 후보를 기존 native 6-DOF 운동방정식과 실제 구동기
응답 모델로 처음부터 적분한다. 관측값으로 모의 상태를 덮어쓰거나 운동방정식에
오차 보정 힘을 추가하지 않는다.

기존 `project2_*` 물리 검증, `flight_reconstructed_*` 비교 결과와 LCvx 연착륙
시나리오는 보존한다. 기본 시나리오나 공통 기체·환경 모델을 변경하지 않는다.

## 기존 궤적이 점점 벌어진 이유

1. 상승 입력은 스로틀 세 값과 10–12초의 짐벌 명령 하나뿐이었다. 초기 상태가
   같아도 이후 추력 크기와 방향의 차이가 속도·위치 오차로 누적된다.
2. 회복 구간은 일정 스로틀, 중립 핀, 수동 자세 운동을 사용했다. 초기 수직 속도는
   100 m 단위 고도 표시의 짧은 미분에서 추정했고 공력계수도 가정값이었다.
   총속력이 맞아도 속도 방향과 항력·양력이 다르면 이후 고도와 속력을 함께
   맞추기 어렵다.
3. 다음 구간의 초기화에 사용한 약 6초를 모든 구간의 평가와 입력 추정에서
   제외했다. 특히 동력 하강의 18초 이후 입력은 기존 평가에 영향을 주지 않았다.
   같은 제외 규칙으로 입력을 추정하면 구간 후반을 제약할 수 없다.
4. LCvx 착륙은 가정한 지상 목표로 연착륙하는 문제를 푼다. 관측 시간 이력을
   재현하는 목적함수가 없으므로 먼저 접지하는 해를 선택할 수 있다.

## 바꾼 추정 문제

설정과 공학적 탐색 범위는
[flight_calibration.yaml](../../configs/analysis/flight_calibration.yaml)에 있다.
범위·정규화 척도·정규화 항은 측정 오차나 통계적 신뢰구간이 아니다.

| 대상 | 추정 변수 | 유지한 조건 |
|---|---|---|
| 상승 | 스로틀 6개, 작은 짐벌 명령 6개 | 초기 상태·질량·기체·엔진·대기·지구 모델 |
| 회복 3구간 공동 | 재진입 스로틀 3개, 초기 비행경로각 3개, 초기 자세 편차 2개, 공통 공력계수 배율 4개, 동력 하강 스로틀 4개·점화 지연, 재진입 초기 질량 | 관측 초기 고도·총속력, 방위각, 엔진 하드웨어·구동기 한계 |
| 착륙 | 이전 추정 초기 고도를 유지하고 LCvx 종단 시각·추력 변화율·추종 이득 설정 | LCvx/PD 폐루프, 현실적 구동기, 앞 구간 종료 질량·스로틀 상태 |

공력 배율은 base drag, transonic drag rise, high-Mach drag rise, normal force에
각각 적용한다. `cd_alpha`에는 base drag와 같은 배율을 적용한다. **각 배율은
회복 네 구간에서 공유**한다. 구간마다 다른 대기나 다른 엔진 성능을 부여하지 않는다.
Mach에 따른 항력 형태를 모두 같은 비율로 고정하면 저속·고속 오차를 동시에
줄이기 어려워 배율을 나누었다. 중립 핀과 무풍·슬로싱 없음 조건은 유지한다.

Bounded least squares가 시간 가중 고도·속력 잔차와 약한 정규화 항을 줄인다.
고도 100 m, 속력 10 m/s의 목적함수 척도는 기존 비교 척도와 같다. 구간과
관측량을 같은 비중으로 취급한다. 수치 Jacobian 계산까지 실제 후보 평가 횟수에
포함하고, 평가 한도 종료와 수치 수렴 종료를 구별해 저장한다. 초기 추정에는
예비 탐색의 후보를 사용한다. 전역 최적해나 유일한 실제 입력을 찾았다는 의미는 아니다.

**입력 추정**에는 각 구간 시작 이후의 모든 품질 유효 관측을 사용한다. 다음
구간의 초기화에 쓴 관측도 여기에 포함하므로 후반부 입력을 제약할 수 있다.
**전후 비교 지표**에는 원래의 초기화·품질 제외 규칙을 그대로 적용한다.
이는 독립 검증용 데이터 분할이 아니며, 같은 관측에 맞춘 재구성의 설명 지표다.

평가에 사용할 표본과 시간 가중치는 탐색 전에 고정한다. 모의가 일찍 끝나면
남은 관측을 누락한 작은 오차를 인정하지 않고 후보를 거부한다. 추진제 부족,
수치 비정상, 공력표 영역 초과, 모의 시간 부족도 후보 거부 사유다.

## LCvx·PD 폐루프 착륙

`flight_calibrated_landing`은 `flight_reconstructed_landing`의 LCvx/PD 구조를
상속하고 **realistic 구동기**를 사용한다. 미리 맞춘 스로틀 시간표는 제거했다.

- LCvx가 현재 초기 위치·속도·질량에서 지상 목표까지의 계획을 계산한다.
- 계획 추종기는 **20 ms마다 현재 추정 위치·속도**로 추력 명령을 보정한다.
- PD 제어기는 현재 자세·각속도로 요구 토크를 계산하고 TVC로 실현한다.
- 항법은 기존과 같이 `IdentityNav`다. 센서 기반 항법 성능을 검증한 결과는 아니다.

LCvx 계획의 종단 시각을 시작 후 **12.145초**로 지정했다. 공개 속력 자료의
끝을 이용한 공학적 경계조건이며 실제 접지 시각으로 확인된 값이 아니다.
항력 보정 SOCP도 이 종단 시각을 유지한다. `convex_replan=false`는 계획을
한 번 확정한다는 의미이며, 매 제어 주기의 상태 피드백과 PD 제어는 계속 작동한다.
이 옵션의 기본값은 `convex_touchdown_time_s=null`이므로 다른 시나리오의
기존 자유 종단 시각 탐색은 유지된다.

단순한 연료 최소화 계획은 급격한 추력 변화와 조기 감속을 선택할 수 있어,
계획 추력 크기의 변화율을 **30 kN/s**로 제한했다. 이는 하드웨어 한계보다
보수적인 유도 제약이다. 계획 항력계수는 저 Mach 공력표에 가까운 **2.0**,
수직 추종 이득은 위치 **6 s⁻²**, 속도 **4 s⁻¹**로 설정했다. 수평 이득과
PD 자세 제어 구조는 유지했다.

종단 위치는 지면 목표에 고정하고, 수평 속도는 0, 수직 하강 속도는
**0–0.5 m/s**의 hard constraint로 지정했다. 종단 slack과 조기 cutoff 보정은
사용하지 않는다. 모의는 실제 지면 접촉까지 계속하며 기존 연착륙 판정 기준을
적용한다. 추력·구동기 지연·변화율 제한·기체 운동방정식도 그대로 적용한다.

초기 고도는 앞서 100 m 단위 표시 범위를 가정해 얻은 **348.764 m**를 유지한다.
이는 표시값 300 m의 실제 센서 오차가 확인되었다는 의미가 아니다. 초기 총속력은
관측값을 유지하고 수직 하강·수직 자세를 가정한다. 초기 질량과 중심 엔진 스로틀
상태는 보정된 동력 하강의 종료값을 전달한다. 실제 착륙장 위치는 확인되지 않아
가정한 초기 지상 투영점을 목표로 사용한다.

이전 개루프 접근 결과는 `results/verification/flight_calibration_final_20261110/`에
과거 기록으로 보존한다. 현재 `flight_calibrated_landing` 실행 결과와 혼용하지 않는다.

## 결과와 검증

기존과 같은 평가 규칙과 **공통 비교 시간**에서 얻은 RMSE다.

| 구간 | 고도 RMSE 기존 → 수정 [m] | 속력 RMSE 기존 → 수정 [m/s] |
|---|---:|---:|
| 상승 | 51.28 → 32.79 | 28.61 → 2.23 |
| 재진입 연소 | 136.65 → 93.92 | 25.96 → 6.53 |
| 공력 하강 | 599.30 → 139.17 | 66.37 → 13.51 |
| 최종 동력 하강 | 273.75 → 46.77 | 32.88 → 14.49 |
| 폐루프 착륙 | 72.71 → 28.10 | 10.94 → 0.97 |

착륙 속력은 기존과 겹치는 6.040초에서 RMSE **0.97 m/s**다. 전체 유효 속력
관측 **12.112초**에서도 RMSE **1.11 m/s**를 얻었다. 시작 후 **12.230초**에
실제로 접지했고, 접지 속력 **0.483 m/s**, 가정한 목표 위치 오차 **0.0138 m**,
잔여 주 추진제 **8.076 t**로 기존 연착륙 기준을 만족했다.

![기존 궤적·수정 궤적·관측 비교](../../results/verification/flight_calibration_closed_loop_final_20261110/comparison.png)

상승 탐색은 80회 후보 평가 한도로 종료했고 전역 또는 국소 최적 수렴을 주장하지
않는다. 회복 공동 추정은 `ftol` 조건으로 종료했다. 현재 착륙에서는 스로틀
시간표 탐색 대신 LCvx 유도와 상태 피드백을 실행한다. 회복 추정의
초기 질량은 **44.000 t**로 상한에 도달했고, 천음속 항력 배율 **0.500**과
일부 스로틀 **0.400**, 점화 지연 **5.900초**도 탐색 경계에 도달했다. 최적화가
종료됐다는 사실은 모델이나 범위가 충분하다는 증거가 아니다. 남은 오차를 줄이려면
추가 자료로 공력·자세·점화 가정을 재검토해야 한다.

추정된 공통 공력 배율은 base **1.84976**, transonic **0.50000**, high-Mach
**0.92398**, normal **1.99891**이다. 이 값은 실측 공력계수가 아니다.
공력 하강의 종료 상태는 약 **4,468 m·274.6 m/s**로, 다음 구간의 관측 기반
초기값 **4,700 m·319.7 m/s**와 아직 차이가 있다. 독립 초기화한 구간들의
RMSE 개선이 연속 전 비행의 재현을 뜻하지 않는다.

다섯 구간의 기록 상태·구동기 한계·질량 수지 검사를 수행한다. 첫 네 구간은
독립 운동방정식 적분과 1 / 0.5 / 0.25 ms 시간 간격 검사를 사용한다.
폐루프 착륙은 실제 접지 성능과 2 / 1 / 0.5 ms에서의 폐루프 시간 간격 비교를
검사한다. 지정 입력용 독립 적분을 폐루프 검증에 적용했다고 주장하지 않는다.
초기 pitch ±1°에서도 연착륙을 확인하고, 같은 계획·시각에서 추정 속도·각속도를
바꾸면 실제 스로틀·짐벌 명령이 달라지는 회귀 테스트로 피드백 연결을 검사한다.
전체 **470개 pytest 테스트와 Ruff 검사**도 통과했다.

[LCvx 계획과 실제 폐루프 궤적 비교](../../results/verification/flight_calibration_closed_loop_20261110_verified/landing/plots/plan_tracking.png)와
[착륙 검증 수치](../../results/verification/flight_calibration_closed_loop_20261110_verified/landing/verification.json)를 함께 보존했다.

현재 결과는 `results/verification/flight_calibration_closed_loop_final_20261110/`,
일반 실행·검증·리플레이는
`results/verification/flight_calibration_closed_loop_20261110_verified/`에 보존한다.
`results/`는 git 추적 대상이 아니므로 배포 시에는 재생성해야 한다. 추정된 시나리오
YAML과 이 설명서는 저장소에 포함된다.

이 다섯 구간은 위치·속도·자세가 독립 초기화된다. 회복 구간 사이에는 계산된
종료 질량과 RCS 가스를 전달하고, 동력 하강→착륙에는 스로틀 상태도
전달한다. 전 비행의 연속 궤적이나 실제 3D 경로·자세를 복원한 결과가 아니다.
고도·총속력만으로 질량·공력·입력·자세를 유일하게 식별할 수 없다.

## 실행

추정된 설정은 저장소의 `flight_calibrated_*` YAML에 포함된다. 탐색을 다시
실행하지 않고 일반 시뮬레이터와 리플레이를 사용할 수 있다.

```bash
.venv/bin/python scripts/run_single.py \
  scenario=flight_calibrated_ascent \
  hydra.run.dir=results/calibrated/ascent
.venv/bin/python scripts/view_replay.py results/calibrated/ascent --system
```

폐루프 착륙만 실행하려면 다음 명령을 사용한다.

```bash
.venv/bin/python scripts/run_single.py \
  scenario=flight_calibrated_landing \
  hydra.run.dir=results/calibrated/landing
.venv/bin/python scripts/view_replay.py results/calibrated/landing --system
```

다른 구간은 `flight_calibrated_entry_burn`, `flight_calibrated_aero_descent`,
`flight_calibrated_powered_descent`, `flight_calibrated_landing`으로 선택한다.

새 출력 경로에서 첫 네 구간의 입력 추정과 폐루프 착륙을 재현하고 설정을 생성한다.

```bash
OPENBLAS_NUM_THREADS=1 .venv/bin/python scripts/calibrate_flight.py \
  --output results/verification/flight_calibration_repeat --write-configs
```

저장한 설정의 물리·수치 검증과 일반 실행 파일을 새로 생성한다.

```bash
OPENBLAS_NUM_THREADS=1 .venv/bin/python scripts/verify_flight_calibration.py \
  --output results/verification/flight_calibration_verified_repeat
```

기존 첫 네 구간 탐색을 재사용하면서 폐루프 착륙을 재계산하려면 새 출력 경로와
`--reuse-input-searches results/verification/flight_calibration_final_20261110`을 사용한다.

완료한 탐색을 재사용하려면 같은 출력 경로·평가 한도에 `--resume`을 추가한다.
설정 일치, 탐색 범위, 물리 검사와 재계산된 잔차를 대조한 후 재사용한다.

탐색 결과에는 목적함수·파라미터·종료 이유·후보별 거부 사유와 비교 그림을
저장한다. 검증 실행에는 `resolved_config.yaml`, `physics.npz`, `actuators.npz`,
`flight_comparison.json`, `replay.json`, `verification.json` 등을 저장한다.
첫 네 구간의 독립 적분과 착륙의 폐루프 접지·시간 간격 검사는 수치·모델
구현의 일관성을 확인하며 실제 Falcon 9의 파라미터 정확도를 입증하지 않는다.
